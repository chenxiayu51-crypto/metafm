# E3 Acceptance Report

Acceptance evidence for the E3 five-corpus pretraining release. Every line below
records something that was actually executed on 2026-10-15; anything not
executed is listed explicitly in §5 as **not verified**.

Machine summary: **all executable checks passed.** Nothing here claims a result
on the real corpora or on A800 hardware.

## 4. Resume and its guard

| scenario | observed |
|---|---|
| resume with unchanged configuration | `COMPLETE`; global step 5 and `ema_updates: 5` restored from the checkpoint; `checkpoint_source: resume_input` |
| resume with `max_steps` changed 5 → 8 | **refused to start**, exit 2, `resume configuration mismatch for max_steps` |

The second row is the intended behaviour: a resumed run with changed training
semantics must fail loudly rather than silently train something different.

## 6. Not verified

These were **not** run, and no pass is claimed for them:

1. **Real five-corpus data.** The official emg2pose, emg2qwerty and GNI corpora
   were not present. No real `nature_corpus.csv` was available, so the official
   interval path is verified by contract and by synthetic analogue only.
2. **A800 / A100 hardware.** No such GPU on this machine. The `e3_server`
   profile is `devices: auto` on one device; multi-GPU DDP was not exercised.
3. **Full 100000-step training.** The longest run was 5 steps by design.
4. **Convergence, loss trajectory and downstream accuracy.** Nothing here
   supports a claim about model quality. Synthetic metrics prove nothing about
   generalisation.
5. **Actual data conversion.** `prepare_data.py` orchestrates the five existing
   converters, but no real raw corpus was converted in this session; its
   fail-closed branches were verified instead.

## 8. Publishing safely

The existing `codex/local-integration` history contains the removed evidence
files. Pushing that branch publishes them regardless of `.gitignore`, which
only affects future commits.

Publish from a clean branch instead (see the release commands in the final
report), or rewrite history with `git filter-repo` — the latter changes commit
SHAs and is destructive.
